# ข้อความสำเร็จรูปที่วางสั่ง Claude Code

แก้ข้อความใน `< >` ให้เป็นของคุณ

## 1) ตรวจว่าเครื่องพร้อม (ครั้งแรก)

> เช็คให้หน่อยว่าเครื่องพร้อมทำคลิปสไตล์สารคดีไหม รัน `npx hyperframes doctor` แล้วเช็คว่าตัวแปร `PIXABAY_API_KEY` และ `ELEVENLABS_API_KEY` ตั้งไว้และใช้ได้ไหม สรุปว่าอะไรผ่านอะไรไม่ผ่าน **ห้ามพิมพ์คีย์ออกมาในแชท**

## 2) ทำคลิป (แบบเต็ม)

> ใช้สกิล `documentary-clip` ทำคลิปให้ฉัน
>
> - **ไฟล์ดิบ:** `<C:\clips\เรื่องแรก\ฉันพูด.mp4>` (คนพูดหน้ากล้อง)
> - **เนื้อหา/บทผู้บรรยาย:** ใช้บทในไฟล์ `<narrator.txt>` (ดูตัวอย่างที่ `examples/narrator_script_th.txt`) ถ้ายังไม่มี ให้ร่างบทให้ฉันดูก่อนทำต่อ
> - **เสียงผู้บรรยาย:** ElevenLabs โมเดล `eleven_v3` เสียงผู้ชายทุ้มที่เป็นเสียง premade (คีย์อยู่ใน `ELEVENLABS_API_KEY`) สร้างบรรทัดละ 3 รอบแล้วเลือกรอบที่ถอดกลับถูกที่สุด
> - **ภาพประกอบ:** หาจาก Pixabay (`PIXABAY_API_KEY`) และคลิปฉากหนังที่กำลังดัง (ใช้เล่น/ไม่เชิงพาณิชย์) ให้ภาพตรงกับคำพูดทีละจังหวะ
> - **เพลง:** `<ลิงก์ YouTube>` เริ่มที่ `<นาที:วินาที>` ห้ามให้เพลงทำให้เสียงพูดเบาลง
> - **สไตล์/ท่า motion:** ตาม `references/motion-library.md` ของสกิล
> - **ผลลัพธ์:** mp4 แนวนอน 1920×1080 ความดังประมาณ −14 LUFS
>
> ตรวจเองด้วย `check` และ `snapshot` ก่อนเรนเดอร์ แล้วสรุปให้ว่าตรวจอะไรไปแล้ว (ตัวเลขที่วัดได้) และอะไรที่ต้องให้ฉันฟังเอง **ห้ามพิมพ์คีย์ API ในแชท**

## 3) ทำแบบประหยัด token

> ใช้สกิล `documentary-clip` ทำคลิปจาก `<ไฟล์ดิบ>` กับบท `<narrator.txt>` เสียง ElevenLabs เพลง `<ลิงก์>` ทำให้จบในรอบเดียว **ไม่ต้องใช้ subagent ไม่ต้องตรวจซ้ำหลายรอบ** ตรวจแค่ `check` กับ `snapshot` ที่จุดสำคัญ แล้วเรนเดอร์

## 4) แก้งานหลังได้คลิปแล้ว (ตัวอย่าง)

> ซับเล็กไปอ่านยากบนมือถือ ขยายเป็น 52px แล้วเงาให้หนาขึ้น / ช่วงจอดำค้างให้เงียบสนิทและสั้นลงเหลือ 0.8 วินาที / เปลี่ยนภาพตอนคำว่า "<คำ>" เป็น `<ภาพที่อยากได้>` แล้วเรนเดอร์ใหม่
